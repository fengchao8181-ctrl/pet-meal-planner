## 2. 总体架构（双通道）

```
┌─ 小程序 ─────────────────────────────┐     ┌─ 公众号 H5 ──────────────────────┐
│ checkin/report 页 wx.requestSubscribe │     │ 用户关注公众号 → 绑定 unionid      │
│ 成功写入 openid 映射回传 Server        │     │ Server 每日定时任务拼装内容          │
└──────────────┬────────────────────────┘     └───────────────┬──────────────────┘
               │ POST /api/subscription/bind                    │ GET /api/push/daily-content
               ▼                                                 ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ 后端 PushService（服务端下发入口）                                             │
│  · 收 openid/unionid + 场景(sendType)  → 挑选模板 → 调微信 API 下发            │
│  · access_token 集中管理（公众号） → 每日任务 cron 拉内容库 → 逐人推送            │
│  · 推送偏好(enable) + 频率控制 + 退订表 + 下发记录(幂等/回执)                     │
└──────────────────────────────────────────────────────────────────────────────┘
```

## 3. 阶段划分与实现步骤

### 阶段 A：小程序订阅消息真实接入（先打通，价值最高、依赖最少）

目标：一次性订阅消息真正下发成功，把"已开启提醒"从占位变真实。

1. **申请正式模板 ID**：微信公众平台 → 订阅消息 → 选择合适模板（喂食/健康提醒类）。拿到后填入 `config.js.REMIND_TEMPLATE_ID`（以及周报/里程碑模板 ID，各自独立占位）。
2. **授权埋点 3 处**（资料 §8.3 选"情绪最高点"）：
   - 建档完成/结果页 → 引导 `wx.requestSubscribeMessage([REMIND_TEMPLATE_ID, WEEKLY_REPORT_TEMPLATE_ID])`
   - 首次打卡成功 → 补授权（喂食提醒只剩尾部机会）——可做连续多模板一次性弹窗
   - 周报生成 → 补授权（周报模板）
   - 回调 `res[templateId] === 'accept'` 才持久化"已授权"；`reject` 不记录。
3. **后端下发接口**：
   - `POST /api/subscription/bind`：收 `{openid, templateId, scene, status}`，写订阅记录表（openid 级）。
   - `POST /api/subscription/send`（内部/受控）：收 `{openid, templateId, data, page}` → 调 `subscribeMessage.send`。
   - 下发前查"授权计数"（一次性订阅需累计可用次数），用一次扣一次，不足则不发并记录待补授权。
4. **Server 触发点**：喂食作息提醒（到点）、周报生成完成、里程碑达到。由事件→`sendSubscriptionTrigger(scene, openid)` 统一入口。
5. **验收（联调真机）**：真机授权后，服务端手动触发一次 `send` → 微信收到订阅消息 → 点进跳转正确页面；同一场景在授权名额耗尽后不再重复打扰。

### 阶段 B：公众号 H5 每日推送接入（企业每日推送主力）

目标：H5 公众号做到"每天一条"，承载柔性关怀，建立每日在客户生活的存在感。

1. **主体/资质 + 配置**：公众号 appid/appsecret、模板消息接口（服务号）就绪。模板 ID 入 `config.js`（或后端 `.env`）。
2. **access_token 集中管理**：后端 `WechatTokenProvider`，凭证缓存到过期前 5 分钟刷新，多实例共享锁避免刷新风暴。
3. **openid 打通（关键前置）**：
   - 小程序侧：登录后拿 `code` → 后端换 `openid+session_key`，存 `WxIdentity {miniOpenid, unionid?}`。
   - 公众号侧：用户从 H5 链接/关注引导页授权 `snsapi_base` → 拿 `unionid`。
   - 用 **unionid 或手机号绑定** 关联同一客户 → 建立 `petKey ↔ unionid ↔ miniOpenid` 映射。
4. **每日定时任务**：服务端 cron 每日早晨（如 08:00，可配置窗口）：
   - 读取当日推送内容（来自 `miniprogram/utils/push-library.js` 内容库或后端模板库）。
   - 遍历已绑定可下发客户 → 按各自场景（有未打卡？有周报？里程碑？）拼装——纯关怀则通用，命中事件则带个性化数字。
   - 调用公众号模板消息下发，记录 `push_log`（幂等：同 petKey+date+scene 不重发）。
5. **内容与频率保护**：单客户每日最多 1 条；命中"更值得"的事件（周报/里程碑）时当天优先发事件内容，不让位柔性关怀覆盖关键消息。
6. **退订机制**：公众号服务通知侧支持退订入口；模板消息内带轻量"不再提醒"链接 → 置入退订表，task 跳过该用户。

### 阶段 C：推送偏好 + 频率控制 + 下发记录（稳健运营）

1. **偏好表** `push_pref {unionid, dailyFeedOn, reportOn, milestoneOn, quietHours}`，默认全开，微信侧与小程序内均可管理。
2. **频率控制**：全局单日总量封顶 + 单用户每日 1 条；错误/失败重试指数退避，杜绝刷屏。
3. **下发记录与回执**：`push_log {id, unionid, channel, scene, sentAt, wxErrCode, open?}`，供次日回访与退订统计。

### 阶段 D：联调验收与上线

1. **真机全链路**：关注公众号→授权→次日 08:00 收到每日推送→点击回小程序；订阅消息关键触发命中一次下发。
2. **测试注入**：`test/push.smoke.cjs`（用 Mock 微信网关回执）验证：下发路由、幂等、额度扣减、退订跳过、openid 绑定。
3. **埋点**：下发成功数、打开数、次日回访、打卡率，对照北极星。
4. 全绿后并入 main；正式密钥仅存在于部署环境 `.env`，不入库。

## 5. 决策面（实现时需确认）

1. **小程序订阅消息模板数量与一次性授权策略**：一次弹多个模板（喂食+周报）提高"一次授权多场景"，但可能吓退用户；建议先弹 1 个最高价值（喂食提醒），周报另设入口。
2. **openid 打通方式**：优先 unionid（需开放平台账号）；暂无开放平台时用手机号在引导页绑定作为降级。
3. **每日推送时段**：默认早晨 08:00，允许用户在偏好里调"静默时段"，清晨喂食场景契合宠物主作息。

## 6. 明确不做（本计划不覆盖）

- 小程序长期订阅（宠物类目不可申请，见设计 §8.1）。
- 由推送驱动的自动下单/自动扣费（推送只做触达，交易仍手动确认）。
- 多语言/多品牌内容路由；首期单人设 H5 内容即可放量。
